# voice-service — отладка микрофона в локальной сети

Страница: **http://node1:8092** (или http://192.168.0.111:8092)

## Что делает

Берёт звук **с микрофона самого сервера** (PulseAudio → `parec`), поэтому браузеру
не нужен доступ к своему микрофону и не нужен HTTPS: страница показывает то, что
реально слышит USB-микрофон на node1.

- Визуализация амплитуды во времени (огибающая, ~19 с истории) + мини-осциллограф последних 100 мс.
- Полоса уровня в dBFS с удержанием пика и индикатором клиппинга.
- **Record** — запись в WAV (16 кГц, моно, s16le) на сервере, **Stop** — сохранение.
- **Play** — проигрывание выбранной записи (клик по записи в списке тоже играет).
- Список записей с длительностью и удалением; устройство выбирается в выпадающем списке
  (по умолчанию — USB-микрофон).

## Архитектура

```
браузер  ──SSE /api/stream──  server.js (Node, без зависимостей)  ──parec──  PulseAudio  ──  USB-микрофон
         ──POST /api/record/*──┘                                  └─ WAV в recordings/
```

Один процесс `parec` на всех клиентов (у USB-карты одно capture-устройство).
Поток: 16 кГц, моно, кадры по 40 мс; в браузер уходят уровни (RMS/пик/dB) и base64-PCM.
Запись пишется тем же потоком, без второго захвата устройства.
Захват сам останавливается через 8 с после закрытия последней вкладки (если нет записи).

## Настройки (env)

`PORT` (8092), `HOST` (0.0.0.0), `RATE` (16000), `CHUNK_MS` (40), `SOURCE`, `IDLE_STOP_MS` (8000).

## Запуск

pm2: `pm2 start server.js --name voice-service`, автозапуск — через `pm2-r.service` (`pm2 save`).

## Микрофон (проверено 2026-11-15)

- Устройство: `card 1: USB PnP Sound Device` = **Texas Instruments PCM2902** (08bb:2902),
  запись только моно, 44100/48000 Гц, один subdevice.
- PulseAudio source: `alsa_input.usb-C-Media_Electronics_Inc._USB_PnP_Sound_Device-00.analog-mono`.
- По умолчанию источник в PA — S/PDIF (тишина), поэтому сервис сам выбирает USB-источник.
- Уровень по умолчанию был очень низкий: ALSA `Mic Capture Volume` = 0/16, PA volume 40 %.
  После `scripts/setup-mic.sh` (ALSA +23.8 dB, PA 150 %) тон 700 Гц даёт ≈ −25 dBFS.

## Важно про parec

Без `--latency-msec` parec отдаёт данные буферами ~2 с и **теряет хвост** записи
(запись на 5 с давала 3.6 с). Поэтому в аргументах жёстко:
`--latency-msec=20 --process-time-msec=20` — длительность записи совпадает с реальной.

## Голосовой ввод и вывод (добавлено 2026-11-15)

### Ввод: Vosk / Kaldi

- Модель: `vosk-model-small-ru-0.22` (88 МБ, лежит в `/home/r/voice_bot/`), движок — Python-пакет
  `vosk` (0.3.45, установлен в venv `/home/r`, запуск через `/home/r/bin/python3`).
- Воркер `asr_worker.py` читает raw PCM s16le 16 кГц моно из stdin и печатает JSON-строки:
  `ready` / `partial` / `final`. Node пишет в его stdin те же кадры, что отдаёт браузеру.
- Слово-обращение (по умолчанию «антон»): сравнивается нормализованный текст (нижний регистр, ё→е,
  пунктуация вырезана), допускается расстояние Левенштейна ≤ 1. Всё, что сказано после обращения,
  склеивается и уходит в историю после паузы `silenceMs` (по умолчанию 1200 мс).
  Чекбокс «только после обращения» можно снять — тогда в историю попадает любая распознанная фраза.
- Кнопка «Включить распознавание» поднимает и захват, и воркер; выключение всё останавливает.
- История ввода хранится в `data/history.json` (последние 50 фраз), настройки — в `data/config.json`.
- Отладка без микрофона: `POST /api/asr/simulate {"text":"антон включи свет"}` прогоняет фразу
  через ту же логику обращения.

### Вывод: eSpeak NG

- Бинарь в `~/.local/opt/espeak-ng` (нужен `LD_LIBRARY_PATH` и `--path`), альтернативно берётся
  `/usr/bin/espeak-ng`, если он появится. В синтезе: голос (`ru`, `ru+f2..f5`, `ru+m1..m7`,
  `ru+whisper`), скорость 80–450 слов/мин, тон 0–99, громкость 0–200.
- WAV кладётся в `tts/` и раздаётся по `/tts/<file>`; сервер сам снимает mute с sink,
  проигрывает через `paplay` и возвращает mute обратно (локальный звук node1).
- Ответ `/api/tts` содержит `url`, `duration`, `played`; страница даёт плеер для прослушивания в браузере.

### Второй движок вывода: RHVoice

- Установлен без root из пакетов Debian (non-free) в `~/.local/opt/rhvoice`:
  `rhvoice` (утилита `RHVoice-test`), `librhvoice5`, `librhvoice-core7`, `librhvoice-audio2`,
  `rhvoice-russian` (13 русских голосов), `rhvoice-english` (7 английских), плюс зависимости
  `libsonic0`, `libao4`, `libportaudio2` — распакованы через `dpkg-deb -x` в тот же префикс.
- Запуск: `RHVOICE_DATA_PATH=<prefix>/usr/share/RHVoice LD_LIBRARY_PATH=<prefix>/usr/lib/x86_64-linux-gnu
  RHVoice-test -p <voice> -r <rate%> -t <pitch%> -v <volume%> -o out.wav`, текст — в stdin.
- Голоса: 20 (13 ru + 7 en), читаются из `voices/*/voice.info` (name/language/gender),
  русские показываются первыми. Формат вывода — WAV 24 кГц моно.
- В API движок выбирается полем `engine`: `espeak` | `rhvoice`; параметры у RHVoice — `rate`
  (50–200 %), `pitch` (50–200 %), `volume` (0–100 %). Выбранный движок и параметры каждого движка
  запоминаются в `data/config.json` (старый плоский формат конфига миграции подхватывает).
- `GET /api/tts/options` теперь отдаёт `engines: [{id,name,available,voices,params,defaults}]`;
  если RHVoice не установлен, страница блокирует переключатель и пишет «движок не установлен».
- Скорость: синтез ~0.4–0.5 с на короткую фразу, качество заметно живее eSpeak.

### Третий движок вывода: Piper

- Бинарь: `piper-tts 1.8.0` из PyPI (ставится в venv `/home/r`, скрипт `~/bin/piper`);
  резервный вариант — официальный `piper_linux_x86_64.tar.gz` распакован в `~/.local/opt/piper/piper`.
  Сервис сам выбирает современный бинарь (по наличию флага `--data-dir` в `--help`) и подставляет нужные флаги.
- Голоса — с HuggingFace `rhasspy/piper-voices`, все четыре русских medium: denis, dmitri, irina, ruslan
  (по 63 МБ, лежат в `~/.local/opt/piper/voices`, всего ~250 МБ). Новый голос = положить `*.onnx` и `*.onnx.json` в эту папку,
  сервис подхватит при следующем запросе. Голоса без `.onnx.json` пропускаются — Piper без конфига не стартует.
- Параметры: `--length_scale` (темп: меньше — быстрее, 0.5–2.0), `--noise_scale` (вариативность, 0–1.2),
  `--sentence_silence` (пауза между фразами, 0–1 с). Выход WAV 22.05 кГц моно, RTF ~0.3 (быстрее реального времени).
- В конфиге: `tts.piper = {voice, lengthScale, noiseScale, sentenceSilence}`; движок запоминается вместе с остальными.
- Известная особенность: старый бинарь 2023.11 падает на голосе denis (`"aɪ" is not a single codepoint`),
  поэтому по умолчанию используется piper 1.8 из pip.

## VAD (Silero)

Без VAD в Vosk уходил весь поток: тишина и шум тоже гонялись через Kaldi. Теперь есть опциональный
Silero VAD перед распознавателем (галочка «Silero VAD» + «Порог VAD» в форме ввода).

- Модель: `silero_vad.onnx` (2.3 МБ) в `~/.local/opt/silero-vad`, инференс через `onnxruntime`
  (он уже стоит вместе с piper-tts). CPU: ~66× быстрее реального времени, отдельного процесса не нужно.
- **Важно**: модель ждёт кадр 512 сэмплов 16 кГц **вместе с 64 сэмплами контекста** — на чистом 512-кадре
  она отдаёт ~0.01 на любой речи. В `asr_worker.py` кадр склеивается с хвостом предыдущего, как в официальной обёртке.
- Логика: pre-roll ~384 мс (чтобы не срезать первый слог), гистерезис по порогу, после конца речи в Vosk
  досылается ещё 600 мс тишины — этого хватает, чтобы Kaldi закрыл фразу своим endpointing (0.5 с) и отдал final.
- События в SSE: `asr {type:"vad", speech, prob}`, на странице — бейдж «речь/тишина» рядом с состоянием.
- Настройки: `asr.vad` (вкл/выкл) и `asr.vadThreshold` (0.05–0.95, по умолчанию 0.5); применяются с перезапуском воркера.
- Замер на реальном потоке: вероятность 1.0 на речи и ~0.03 в паузах; синтетическая речь (piper через динамик)
  уверенно ловится как речь, а вот распознаётся она хуже живой — это уже ограничение модели Vosk.

### LLM (DeepSeek)

Блок «LLM» связывает голосовой ввод и вывод: распознанная команда уходит в модель, ответ
проговаривается текущим движком синтеза (eSpeak / RHVoice / Piper).

- Провайдер — DeepSeek, OpenAI-совместимый `api.deepseek.com` (адрес можно переопределить `LLM_BASE_URL`).
  Ключ сервис берёт **только** из `.env` в корне проекта или из переменной окружения `LLM_API_KEY`.
  Файл `.env` (права 600) в `.gitignore` и в репозиторий не попадает; в браузер ключ не отдаётся.
  Шаблон — `.env.example`: `cp .env.example .env && chmod 600 .env`, затем вписать ключ.
- Список моделей — из `GET /models` того же провайдера (кэш 10 минут), а не из конфига OpenClaw.
  Сейчас отдаёт `deepseek-flash` и `deepseek-v4-pro`.
- Поля формы: включение, модель (список из `GET /models`), thinking (по умолчанию выкл), stream (по умолчанию вкл),
  `max_tokens` (по умолчанию 300), системный промпт. Дефолтный промпт: «Ты голосовой ассистент.
  Отвечай по-русски, кратко и естественно. Не используй Markdown.»
- thinking выключен → в запросе `thinking: {type: "disabled"}` (проверено: `reasoning_content` пустой, ответ быстрее).
  Включён → `{type: "enabled"}`. Важно: при включённом thinking модель тратит max_tokens на размышления —
  на 50 токенах ответ приходил пустым, поэтому дефолт 300 и при включении thinking стоит поднимать.
- stream: ответ читается по SSE, режется на законченные фразы (по `. ! ? …`) и каждая фраза сразу уходит в синтез и
  воспроизведение — ассистент начинает говорить, не дожидаясь всего ответа. Без stream озвучивается целиком.
- **Продолжение диалога** (галочка «продолжать диалог без обращения» + «Окно, с», по умолчанию 10):
  после того как ответ договорён, сервис ещё `N` секунд принимает голосовой ввод **без слова-обращения** —
  сказанное уходит в LLM как продолжение беседы, и окно открывается снова после следующего ответа.
  Пока идёт синтез/произношение ответа, распознанные фразы игнорируются — чтобы микрофон не слышал сам себя.
  В UI бейдж показывает «ждёт продолжения», в SSE приходит событие `llm {type: "followup", until}`.
- **Стоп-слово** (поле «Стоп-слово», по умолчанию `стоп`): сказать «<обращение> <стоп-слово>»
  можно в любой момент, даже пока ассистент говорит — сервис обрывает текущий ответ: убивает `paplay`,
  чистит очередь фраз, рвёт HTTP-запрос к LLM, закрывает окно продолжения и очищает контекст диалога.
  Защита от хвостов — счётчик поколения (`llm.gen`) и токен воспроизведения, чтобы уже
  синтезированные, но не проигранные фразы не зазвучали после остановки. В SSE — `llm {type:"stopped"}` и `asr {type:"stop"}`.
- История диалога — последние 8 сообщений в памяти сервиса (кнопка «Новый диалог» очищает). Кнопка «Спросить» —
  проверка текстом без микрофона.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/llm/options` | модели, конфиг, наличие ключа |
| POST | `/api/llm/config` | `{enabled, model, thinking, stream, maxTokens, systemPrompt}` |
| POST | `/api/llm/ask` | `{text}` — ответ + озвучка |
| POST | `/api/llm/reset` | очистить историю диалога |

SSE-события `llm`: `start`, `delta`, `done`, `speaking`, `error`, `config`.

### Системный звук

Секция «Системный звук» управляет тем же PulseAudio/ALSA, что использует сервис, — без ssh.

- **Вывод**: выбор sink, громкость 0–150 %, mute, «По умолчанию», «Проверить» (короткий тон 660 Гц
  через `paplay --device=<sink>`; если sink в mute, страница об этом предупредит).
- **Ввод**: выбор source, громкость, mute, «По умолчанию» + аппаратные контролы ALSA той карты,
  к которой относится выбранный source (у USB-микрофона это `Mic` 0–16 и `Auto Gain Control`).
  Поэтому лечить «тихий микрофон» можно прямо из браузера, не заходя в `alsamixer`.
- Состояние читается из `pactl --format=json list sinks|sources` + `amixer sget`; меняется через
  `pactl set-sink-*` / `set-source-*` / `amixer sset`. В конфиг сервиса ничего не пишется —
  это состояние звуковой подсистемы.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/audio?source=NAME` | sinks, sources, default'ы и ALSA-контролы карты источника |
| POST | `/api/audio/sink` `/api/audio/source` | `{name, volume?, mute?, setDefault?}` |
| POST | `/api/audio/card` | `{card, control, value}` → `amixer sset` |
| POST | `/api/audio/test` | `{sink?}` → короткий тон |

### Bluetooth

Секция для сценария «колонка вместо встроенного выхода». Управляет тем же BlueZ, что и `bluetoothctl`.

- **Адаптер**: состояние (включён/выключен, адрес), кнопки «Сканировать» (8 с), «Включить/Выключить»,
  «Обновить». Состояние само обновляется раз в 12 с, пока вкладка активна.
- **Устройства**: имя, MAC, метки «сопряжено»/«подключено», кнопка «Подключить»/«Отключить».
  Устройства без имени показываются как «неизвестное устройство» (это случайные MAC из эфира).
- **Сделать выводом** появляется, когда у устройства есть A2DP-sink `bluez_sink.*`: кнопка
  переключает default sink, снимает mute и обновляет блок «Системный звук» — после этого TTS и
  «Проверить» играют в колонку.
- Если устройство подключилось, а sink не появился, строка помечается «нет A2DP-профиля» с подсказкой
  про greeter (см. AGENTS.md: `pkill -u lightdm pulseaudio` + перезапуск user-pa).
- Ошибки BlueZ переводятся на человеческий: `br-connection-page-timeout` → «устройство не отвечает
  (выключено или вне зоны)».

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/bluetooth` | адаптер, устройства, их sink'и |
| POST | `/api/bluetooth/scan` | `{seconds?}` — сканирование |
| POST | `/api/bluetooth/connect` `/api/bluetooth/disconnect` | `{mac}` |
| POST | `/api/bluetooth/trust` | `{mac, value}` |
| POST | `/api/bluetooth/power` | `{on}` |

## Проверено

- Запись 5 с → WAV ровно 5.000 с; Play в браузере работает.
- ASR: синтезированная фраза «Антон включи свет» через динамик → история «включи свет» (после обращения),
  обычная речь в комнате распознаётся дословно.
- TTS: `/api/tts` вернул WAV, проиграл на сервере; страница показала плеер.
- Headless Chromium: формы рисуются, состояние «слушаю», ошибок в консоли нет.
